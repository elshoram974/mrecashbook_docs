قاعدة البيانات (Local Database) Database Layer (Drift)

كيف نقوم بحفظ البيانات محلياً باستخدام Drift (SQLite)، وإدارة العلاقات والعمليات المعقدة. How we store data locally using Drift (SQLite), managing relationships and complex operations.

💾 لماذا Drift؟ Why Drift?

يعتبر Drift الخيار الأمثل للتطبيقات التي تحتاج لقاعدة بيانات SQLite قوية مع دعم كامل للـ Streams (تحديث الـ UI تلقائياً عند تغيير البيانات) والأمان من ناحية الأنواع (Type-safety).

Drift is the best choice for apps needing robust SQLite storage with full reactive Stream support (auto-updating UI on data changes) and strict Type-safety.

Feature sqflite Hive Drift
Queries Raw SQL NoSQL Dart / SQL
Reactivity Manual Automatic Streams (Built-in)
Migrations Manual Very Hard Schema Migrator
📊 هيكل الجداول (The Schema) Table Schema

يتكون نموذج البيانات من جداول أساسية مرتبطة ببعضها البعض بعلاقة "واحد لمجموعة" (One-to-Many). كل `Book` يحتوي على العديد من الـ `Entries`.

The data model consists of core tables linked via a One-to-Many relationship. Each `Book` contains multiple `Entries`.

📁 lib/core/database/tables/books.dart
class Books extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get name => text().withLength(min: 1, max: 100)();
  DateTimeColumn get createdAt => dateTime().withDefault(currentDateAndTime)();
  BoolColumn get isIncludedInTotal => boolean().withDefault(const Constant(true))();
  DateTimeColumn get updatedAt => dateTime().withDefault(currentDateAndTime)();
}
📁 lib/core/database/tables/entries.dart
class Entries extends Table {
  IntColumn get id => integer().autoIncrement()();
  IntColumn get bookId => integer().references(Books, #id)();
  RealColumn get amount => real()();
  TextColumn get type => text().customConstraint("NOT NULL CHECK(type IN ('in', 'out'))")();
  DateTimeColumn get date => dateTime()();
  TextColumn get notes => text().nullable()();
}
[Books] Table (PK: id)
    │
    └───[Entries] Table (FK: bookId ──► Books.id)
⚙️ الـ DAOs والعمليات المعقدة DAOs & Complex Operations

الـ Data Access Objects (DAOs) هي المكان الذي نكتب فيه استعلامات البيانات. أحد أهم العمليات هو حساب الرصيد الحي (Live Balance) لكل كتاب.

Data Access Objects (DAOs) are where we write data queries. One of the most important operations is calculating the Live Balance for each book.

📁 lib/core/database/daos/book_dao.dart
Stream> watchBooksWithBalances() {
  final entriesTable = attachedDatabase.entries;
  
  // Custom expression to calculate net balance: SUM(in) - SUM(out)
  final balanceExpression = CustomExpression(
    'SUM(CASE WHEN type = \'in\' THEN amount ELSE -amount END)',
  );

  final query = select(books).join([
    leftOuterJoin(entriesTable, entriesTable.bookId.equalsExp(books.id)),
  ]);

  query.addColumns([balanceExpression]);
  query.groupBy([books.id]);

  return query.watch().map((rows) {
    return rows.map((row) {
      return BookWithBalance(
        book: row.readTable(books),
        balance: row.read(balanceExpression) ?? 0.0,
      );
    }).toList();
  });
}
CustomExpression('SUM(CASE...END)')
🔍 ماذا يفعل؟🔍 What does it do?

يقوم بعمل حساب رياضي داخل استعلام الـ SQL: إذا كان النوع 'in' يجمعه، وإذا كان 'out' يطرحه.

Performs a mathematical calculation inside the SQL query: adds if type is 'in', subtracts if type is 'out'.

🤔 لماذا بهذه الطريقة؟🤔 Why this way?

أسرع بكثير من جلب كل المعاملات وحسابها في Dart؛ قاعدة البيانات تقوم بالعملية في جزء من الثانية.

Much faster than fetching all transactions and calculating in Dart; the DB handles it in milliseconds.

🛠️ إدارة الهجرات (Schema Migrations) Schema Migrations

عندما نقوم بتغيير هيكل الجداول في إصدار جديد، يجب استخدام Migrations للحفاظ على بيانات المستخدم القديمة.

When changing the table structure in a new version, Migrations must be used to preserve existing user data.

📁 lib/core/database/app_database.dart
@override
MigrationStrategy get migration => MigrationStrategy(
  onUpgrade: (migrator, from, to) async {
    if (from < 6) {
      // v5 → v6: Add isIncludedInTotal to books.
      await migrator.addColumn(books, books.isIncludedInTotal);
    }
  },
);
⚠️

هام: لا تغير رقم الـ `schemaVersion` دون كتابة منطق الـ `onUpgrade` المقابل له، وإلا سيفقد المستخدمون بياناتهم!

Important: Never increment `schemaVersion` without writing the corresponding `onUpgrade` logic, or users will lose their data!
