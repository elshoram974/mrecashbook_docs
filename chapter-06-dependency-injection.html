حقن التبعيات (Dependency Injection) Dependency Injection (GetIt)

كيف نجعل كود التطبيق قابلاً للاختبار (Testable) ومنفصلاً عن بعضه باستخدام نمط Service Locator. How we make app code testable and decoupled using the Service Locator pattern.

💉 ما هو الـ DI ولماذا نحتاجه؟ What is DI and why?

حقن التبعيات يعني ألا يقوم الكلاس بإنشاء التبعيات التي يحتاجها بنفسه، بل يطلبها من الخارج. هذا يسمح لنا بتغيير التبعية (مثلاً تبديل قاعدة بيانات حقيقية بأخرى وهمية للتحميل) دون تعديل الكلاس نفسه.

Dependency Injection means a class doesn't create its dependencies itself; it requests them from outside. This allows swapping dependencies (e.g., real DB for a mock one) without modifying the class.

⚠️

بدون DI: الـ Bloc ينشئ الـ Repository بنفسه. (كود متشابك يصعب فحصه).

Without DI: Bloc creates Repository itself. (Tightly coupled code, hard to test).

مع DI: الـ Bloc يستقبل الـ Repository في الـ Constructor. (كود مرن ونظيف).

With DI: Bloc receives Repository in the Constructor. (Flexible and clean code).

🚀 استخدام GetIt (Service Locator) Using GetIt

في Flutter، نستخدم مكتبة `get_it` كمخزن عالمي للتبعيات. نقوم بتعريف كاشف الخدمات `sl` (اختصار لـ Service Locator).

In Flutter, we use the `get_it` package as a global dependency store. We define a service locator `sl`.

📁 lib/core/di/injection_container.dart
final sl = GetIt.instance;

Future initDI() async {
  // 1. SharedPreferences
  final prefs = await SharedPreferences.getInstance();
  sl.registerLazySingleton(() => prefs);

  // 2. Database & DAOs
  sl.registerLazySingleton(() => AppDatabase());
  sl.registerLazySingleton(() => BookDao(sl()));

  // 3. Repositories
  sl.registerLazySingleton(
    () => BookRepositoryImpl(sl(), sl()),
  );
}
sl()
🔍 كيف تعمل؟🔍 How does it work?

عندما يطلب الـ DAO قاعدة البيانات، يذهب لـ GetIt ويقول: "أعطني النسخة المسجلة من AppDatabase".

When a DAO requests the database, it goes to GetIt and says: "Give me the registered instance of AppDatabase".

🔄 الفرق بين Singleton و Factory Singleton vs Factory

طريقة تسجيل التبعية تحدد كم مرة سيتم إنشاء الكلاس وكيف سيتم مشاركته.

How you register a dependency determines how many times the class is created and how it's shared.

registerLazySingleton

يتم إنشاء نسخة واحدة فقط طوال عمر التطبيق. مفيد لقواعد البيانات والخدمات المشتركة.

Creates only one instance for the app's lifetime. Useful for DBs and shared services.

registerFactory

يتم إنشاء نسخة جديدة تماماً في كل مرة نطلب فيها الملف. مفيد للـ BLoCs والـ Cubits لضمان حالة نظيفة في كل سكرين.

Creates a brand new instance every time it's requested. Useful for BLoCs and Cubits to ensure a fresh state for each screen.

💡

نستخدم `registerLazySingleton` بدلاً من `registerSingleton` لضمان أن الكلاس لن يتم تحميله في الذاكرة إلا عند الحاجة إليه فعلياً (Lazy loading).

We use `registerLazySingleton` instead of `registerSingleton` to ensure classes are only loaded into memory when they are actually needed (Lazy loading).
