إدارة الحالة (State Management) State Management (BLoC)

لماذا BLoC؟ وكيف يعمل نظام الـ Reactive Streams لتحديث الواجهة بمجرد تغيير البيانات. Why BLoC? And how the Reactive Streams system updates the UI as soon as data changes.

⚖️ BLoC vs Cubit: متى نستخدم أياً منهما؟ BLoC vs Cubit: When to use which?

في هذا المشروع، نستخدم كليهما بناءً على تعقيد الحالة. نستخدم Cubit للحالات البسيطة و BLoC للحالات التي تعتمد على الـ Streams أو تحتاج لمعالجة متقدمة للأحداث.

In this project, we use both based on state complexity. We use Cubit for simple states and BLoC for states relying on Streams or needing advanced event processing.

AppSettingsCubit (Settings/Theme)
🤔 ليه Cubit؟🤔 Why Cubit?

لأن تغيير اللغة أو الثيم عملية بسيطة (Action -> Reaction) لا تحتاج لتعقيد الـ Events.

Because changing language or theme is a simple process (Action -> Reaction) that doesn't need Event complexity.

BooksBloc (Ledger Logic)
🤔 ليه BLoC؟🤔 Why BLoC?

لأننا نراقب (Listen) لـ Stream من قاعدة البيانات، ونشغل أحداثاً داخلية عند وصول بيانات جديدة.

Because we listen to a Stream from the DB and trigger internal events when new data arrives.

📡 التحديث التلقائي (Reactive Streams) Reactive Streams

أقوى ميزة في هذا التطبيق هي التفاعل اللحظي. بمجرد إضافة معاملة، يتم تحديث الرصيد والرسوم البيانية فوراً دون الحاجة لإعادة تحميل الصفحة.

The most powerful feature in this app is real-time reactivity. Once a transaction is added, balances and charts update immediately without refreshing.

📁 lib/features/books/presentation/bloc/books_bloc.dart
// 1. Subscription to the repository's stream
_booksSubscription = _repository.watchBooks().listen(
  (books) => add(BooksUpdated(books)), // 2. Trigger event when data changes
);

// 3. Handler emits the new state
void _onBooksUpdated(BooksUpdated event, Emitter emit) {
  emit(BooksLoaded(books: event.books));
}
Database (Drift) ──► Stream ──► BooksBloc (Event) ──► UI (State)
🖼️ الربط مع الواجهة (UI Integration) Connecting to UI

نستخدم `BlocBuilder` و `BlocListener` في Screens المشروع لضمان فصل الكود. نطبق قاعدة الـ "Clean Screens": السكرين هي مجرد منظم (Orchestrator).

We use `BlocBuilder` and `BlocListener` in the app screens. We follow the "Clean Screens" rule: the screen is just an orchestrator.

⚠️

تذكر دائماً: لا تضع منطق العمل (Business Logic) داخل الـ `build` ميثود. مهمة الـ `build` هي رسم الواجهة فقط بناءً على الحالة.

Always remember: Do not put business logic inside the `build` method. The `build` method's job is only to draw the UI based on the state.
