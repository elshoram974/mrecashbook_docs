هيكل المشروع والتنظيم Project Structure & Organization

لماذا هذا الترتيب؟ وكيف نجد أي ملف في ثوانٍ باتباع قواعد Clean Architecture. Why this organization? And how to find any file in seconds by following Clean Architecture rules.

📁 شجرة المجلدات الحقيقية The Actual Folder Tree

إليك الهيكل التنظيمي للمشروع كما تم استخراجه من الكود. يتميز التطبيق بتقسيم واضح بين الـ `core` (الأساسيات المشتركة) والـ `features` (الميزات المستقلة).

Here is the organizational structure of the project. The app features a clear split between `core` (shared logic) and `features` (independent modules).

lib/
├── core/                # Shared logic, utils, and global themes
│   ├── database/        # Drift DB setup and tables
│   ├── di/              # Dependency Injection container
│   ├── localization/    # Translations (AR/EN)
│   ├── theme/           # Global colors and text styles
│   └── widgets/         # Reusable UI components
└── features/            # Independent business modules
    ├── auth/            # Biometrics and security
    ├── books/           # Multi-ledger management
    ├── dashboard/       # Statistics and charts
    └── settings/        # App preferences and backup
⚖️ الفرق بين Core و Features Core vs Features

مجلد `core` يحتوي على كل ما هو "عالمي" أو "مشترك". إذا قمت بحذفه، سيتوقف التطبيق بالكامل عن العمل. أما مجلد `features` فيحتوي على المنطق الخاص بكل ميزة، حذف ميزة واحدة لا ينبغي أن يعطل باقي الميزات.

The `core` folder contains everything "global" or "shared". If you delete it, the entire app stops working. The `features` folder contains business logic; deleting one feature should theoretically not break others.

💡

نصيحة: أي Widget تستخدمه في أكثر من ميزتين، انقله فوراً إلى `lib/core/widgets`.

Tip: Any widget used in more than two features should be moved to `lib/core/widgets` immediately.

Layers تشريح الميزة (Feature Anatomy) Anatomy of a Feature

داخل كل ميزة، نتبع التقسيم الثلاثي لـ Clean Architecture لضمان فصل منطق الواجهة عن منطق البيانات.

Inside each feature, we follow Clean Architecture's triple split to separate UI logic from data logic.

/presentation
🔍 محتوياته🔍 Contents

يحتوي على الـ Screens، الـ Widgets الخاصة بالميزة، والـ BLoCs/Cubits.

Contains Screens, feature-specific Widgets, and BLoCs/Cubits.

/domain
🔍 محتوياته🔍 Contents

يحتوي على الـ Entities (نماذج البيانات الصافية) والـ Repositories (واجهات التعامل مع البيانات).

Contains Entities (pure data models) and Repositories (data interfaces).

/data
🔍 محتوياته🔍 Contents

يحتوي على الـ Models (تطوير للـ entities مع دعم JSON/DB) والـ DataSources (التعامل الحقيقي مع API أو DB).

Contains Models (entities expanded with JSON/DB support) and DataSources (actual API or DB interaction).

⚠️

خطأ شائع: كتابة كود الـ Database مباشرة داخل الـ Screen. هذا يدمر مبدأ الـ Clean Architecture.

Common Mistake: Writing database code directly inside a Screen. This destroys the Clean Architecture principle.
